## Publication and runtime limitations

The execution environment currently rejects GitHub Git authentication:
`fatal: could not read Username for 'https://github.com': No such device or address`.
Its network policy also rejects the real GitHub API request:
`<urlopen error Tunnel connection failed: 403 Forbidden>`.
The real synchronizer was invoked and produced a failure proposal while preserving curated pins.
The final `git push --set-upstream` failed with the authentication error above.
The concrete Draft PR attempt failed with `Post "https://api.github.com/graphql": Forbidden`.
Remote subsequent fixes could therefore not be inspected. No branch was force-pushed or merged.

**No v2 Windows EXE, portable ZIP, installer, hosted dependency bundle, successful Windows CI,
development release or Draft PR is claimed to have been published in this session.** The local
branch, source handoff and exact draft PR/release notes are ready; GitHub connectivity/authentication
must be restored to push and run the supplied workflow. Its optional `draft_release` dispatch
creates a draft prerelease only after both Linux and Windows jobs pass.

No physical RTX 4080/5090, Feature 18 evaluation, GPU completion, visual NR contribution,
FiveM client acceptance or stable gameplay was available here. Those results remain real-hardware
acceptance work. A complete permitted route can be installed experimentally without first
proving Feature 18, but its installation is never labelled as successful Neural Rendering.

Unmatched Feeder prereleases, Dagherbou's larger unreviewed deployment set and generic x86/legacy
bridge recipes remain unavailable as complete automatic stacks. Pure/client-prohibited routes
remain blocked. A protected/licensed NR consumer and proprietary NR runtime must be obtained
legitimately/imported locally; AKENO does not mirror them or bypass their loader policy.

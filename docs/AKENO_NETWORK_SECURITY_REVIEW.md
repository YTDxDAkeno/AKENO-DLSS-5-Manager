# Network and modular-installation security review

Status: development review of `feature/akeno-network-modular`; not a release/penetration-test certification.

| Boundary | Implemented control | Remaining risk / required validation |
|---|---|---|
| Optional executable code | Fixed eight-file inventory, SHA-256 and version checks, external source collection, absent-component startup path | A local attacker who can replace Core can replace its inventory too. Inventory authentication comes from the existing signed whole release, not from an untrusted JSON download. Windows packaging/install evidence still needed. |
| Downloads / updates | Existing Ed25519, SHA-256, signed content aggregate, bounded strict extraction, full staging verification before selection, copied-subset verification | No standalone unsigned module download is allowed. The main executable and installer are not Authenticode-signed. False positives, installer-level blocking and module-specific detection are different hypotheses. | Discovery | Not implemented or enabled | Any future broadcast/multicast forwarding must be room-bound, protocol/port allowlisted, rate/size limited, and resistant to cross-room amplification. Explicit-IP game connections are the safer initial target. |
| VPN profile import | Strict WireGuard allowlist, one peer, input bounds, keys/IPs/endpoints/MTU validation, no shell/subprocess execution | Parser validity is not endpoint trust or connectivity. | VPN secrets | Windows DPAPI encrypted SQLite payload, no Linux plaintext fallback; profile text omitted from repr and error messages | Real Windows DPAPI, cross-user and corruption tests pending. | Public relays/providers | None enabled, no fabricated servers/countries | VPN Gate terms, operator privacy/logging, profile validation, explicit consent and availability checks remain unreviewed. Never promise no-logs or free global availability. No commercial private API assumptions. |
| Routing / DNS / privileged service | Explicit UAC/official WireGuard backend implemented in source; not executed on Windows here | Requires authenticated local IPC, fixed operations, least privilege, signed adapters, transaction journal, DNS/IPv6 leak tests, network-change recovery and safe rollback. | Production VPS | API routes are opt-in and disabled by default; no production deployment, firewall or Caddy change | Integrate authenticated APIs in isolation first. Do not turn the licensing VPS into a public exit or relay without explicit deployment approval and capacity/security review. |

## Required release evidence

1. Disposable Windows Full/Core/custom installs, component deselection on an upgrade, user-data retention, uninstall and repair; compile the actual Inno script.
2. Authenticated full ZIP updates, Core-only filtering, missing/corrupt/locked optional files, invalid signatures/hashes, failed health check, interrupted switch and rollback. Confirm Core-only rollback refusal is explained to the user.
3. DPAPI round-trip and wrong-user/tamper checks on Windows; secret-free metadata/logs/diagnostics; no profile/key sync.
4. Only after implementing transport: two real Windows PCs, distinct NATs, direct P2P, own relay fallback, membership revocation while traffic is active, routing/DNS restoration, IPv4/IPv6 leaks, network change/standby and bounded game discovery.
5. Actual named LAN game tests and real packet exchange separately from simulated control-plane tests. Do not mark any of these completed merely because a room allocated two IPs.

## Continuation security delta

- Same-version module install/repair/remove now uses the full authenticated release and existing directory swap. Local selection is written only after payload validation; old selection is retained for rollback. Signed archives carrying the local selection INI are rejected. No standalone unsigned module feed was added.
- LAN APIs are implemented behind an explicit disabled-by-default flag. Existing session/license/email/device binding and account/IP limits protect them; body actor spoofing and device takeover are rejected. Peer credentials have a separate Ed25519 token type/audience/room/device/key/IP and 45-second expiry. Data-plane lease/revocation enforcement and public endpoint proof still need integration.
- The paired UDP relay has source-tuple, lease, live-authoriser, size/format/rate controls and no amplification. It is not exposed as a public endpoint. The trusted allocator must prove endpoints; do not turn fixture tuple injection into an anonymous Internet relay.
- The Windows connector verifies installed WireGuard binaries, selects their directory from an OS known folder and uses only fixed service verbs. UAC is per-operation, requests/results/journal are per-user DPAPI, transient config DACLs apply before writing, and the official manager performs System DPAPI import. Actual Windows/alternate-admin/locked-file/manager/routing/DNS/IPv6 tests remain required; fake backends establish none of those properties.
- Full-tunnel IPv4-only profiles are refused rather than silently permitting IPv6 escape. This is a conservative policy, not a completed leak test. Exit-IP observation requires a fresh handshake and retains normal HTTPS/proxy trust; it does not certify every application's route.
- VPN Gate catalog parsing is implemented, but connection remains unconditionally disabled; live terms/catalog access and OpenVPN review are unresolved. Network allowlist changes saved as a draft are not proof of current access.
- Real Linux userspace WireGuard direct traffic, revocation/reconnect and opaque relay fallback passed in isolated containers. Public ISP NAT, Windows drivers and LAN games remain untested. No production routes, services, firewall, Caddy, user/license state or release private key was modified.

Elevated disconnect now requires the imported profile private key to derive a public key matching the actual native tunnel before removal. It refuses unproven encrypted orphans and foreign keys instead of deleting them. DangerousScriptExecution overrides are refused without changing the registry. Connect enforces the existing AKENO entitlement; safety cleanup remains allowed after expiry. These code paths still require actual Windows/UAC/manager validation.
